# pcaphunt

A Python tool that reads a network capture (`.pcap`) and **hunts for signs of attacks** in it: port scans, ARP spoofing, passwords sent without encryption, and suspicious DNS queries.

Built while learning Python from a networking background, using [Scapy](https://scapy.net/).

## What it detects

| Detection | How it works | Attack it reveals |
|---|---|---|
| **Port scan** | One source sends TCP SYN packets to more than 20 different ports of one target | Reconnaissance, e.g. `nmap -sS` |
| **ARP spoofing** | One IP address is claimed by more than one MAC address in ARP replies | Man-in-the-middle on the local network |
| **Cleartext credentials** | Login keywords (`user`, `pass`, `login`, `Authorization: Basic`) in traffic to FTP (21), Telnet (23) or HTTP (80) | Passwords readable by anyone capturing the traffic |
| **Suspicious DNS** | Query name longer than 60 characters, or one part longer than 30 | DNS tunneling (data hidden in domain names), malware-generated domains |

It also prints a **protocol breakdown** and the **top 5 talkers** (source IPs by packet count).

## Installation

```bash
git clone https://github.com/spyreex/pcaphunt.git
cd pcaphunt
pip install -r requirements.txt
```
On Windows, use `py -m pip install -r requirements.txt` if `pip` isn't recognized.

## Usage

```bash
python pcaphunt.py capture.pcap
python pcaphunt.py capture.pcap --json report.json   # also save results as JSON
python pcaphunt.py --help
```

Captures can be made with Wireshark: *File → Save As → pcap format*.

## Try it with the sample captures

The repo includes synthetic test captures (fake addresses, no real traffic), each containing one type of attack:

```bash
python pcaphunt.py test_scan.pcap     # 200-port SYN scan
python pcaphunt.py test_arp.pcap      # router IP claimed by a second MAC
python pcaphunt.py test_creds.pcap    # FTP and HTTP logins in cleartext
python pcaphunt.py test_dns.pcap      # tunneling-style and very long DNS names
```

They are generated by the `make_test_*.py` scripts, which build packets with Scapy and write them to a file. Nothing is sent on the network.

## Design choices

- **Passwords are masked** in the report (`pass ****`, `password=****`). Usernames are kept, so an analyst knows which account to reset, but the tool never writes the secret itself into a report file.
- **Each detector is tested in both directions**: it must alert on its synthetic attack capture, and stay quiet on real everyday traffic (false-positive check).
- **Duplicate DNS alerts are suppressed**: a suspicious name queried several times is reported once.

## Limitations

- **IPv4 only.** IPv6 packets are counted in the protocol stats but skipped by the detectors and the talkers list.
- **Only TCP SYN scans** are detected. UDP scans (`nmap -sU`) and slow scans spread over a long time are not.
- **Keyword matching for credentials is simple.** It can raise false alarms (e.g. just opening a page called `/login`) and misses logins on non-standard ports. Encrypted traffic (HTTPS, SSH) is correctly not inspected.
- **ARP alerts can be legitimate**, e.g. after replacing a router or with some redundant gateway setups. An alert means "check this", not "definitely an attack".
- **DNS rules use length only.** Some legitimate cloud and CDN hostnames are long. Real tools also measure randomness (entropy) and query volume.
- Thresholds are fixed constants at the top of `pcaphunt.py`.

## Ethics

Only capture and analyze traffic on networks you own or are explicitly allowed to monitor. The included sample captures are synthetic. Never run real attacks (port scans, ARP spoofing) against networks or devices that aren't yours.

## What I learned

Reading binary capture files with Scapy, protocol layers (Ethernet, ARP, IP, TCP, UDP, DNS), TCP flags and the handshake, counting with `Counter` and `defaultdict(set)`, bytes vs text, regular expressions for masking, functions that return results instead of printing, `argparse`, JSON export, and testing detectors with generated attack traffic.
